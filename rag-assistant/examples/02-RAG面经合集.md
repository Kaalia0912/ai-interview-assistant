# AI应用工程师面经合集 · RAG 篇

- 岗位：AI 应用工程师 / RAG 方向
- 说明：本地学习整理的常见面试题与答题要点，非平台原文搬运

## 问题与答题要点

### 1. 完整画出 RAG 离线入库和在线问答两条流程

离线：文档 → 加载 → 清洗 → 分块 → embedding → 存入向量库。在线：问题 →（查询改写）→ embedding → 检索 top-k → 重排 → 拼 prompt → 大模型生成 → 答案 + 引用。

### 2. 为什么要分块？chunk size 和 overlap 怎么定？

模型一次只能读有限长度的上下文，块太大容易塞进无关内容、块太小切碎语义。常见参数：chunk size 300~800 token、overlap 10%~20%，优先按标题、段落、句子边界切；更进阶用父子分块（大块给上下文、小块做检索）。

### 3. embedding 是什么？余弦相似度怎么算？

embedding 把文本变成一串向量数字，语义相近的文本向量距离近。余弦相似度是计算两个向量夹角的余弦值，值越大越相似。注意：查询和文档必须用同一个 embedding 模型，否则维度都不一致。

### 4. 向量数据库怎么选型？HNSW 是什么？

Chroma 轻量、本地文件，适合学习和小项目；FAISS 是单机向量索引库；pgvector 适合已有 PostgreSQL 的场景；Milvus 用于大规模生产。HNSW 是一种基于图的近似最近邻索引，检索快，通常作为默认索引类型。

### 5. 检索结果不好，从哪几个环节排查优化？

按顺序排查：分块是否切碎语义、embedding 模型是否合适、相似度阈值是否过高、查询是否太口语（做查询改写补全代词）、是否只用了向量检索（加 BM25 混合检索）、是否缺重排。

### 6. 重排（rerank）是干什么的？直接取 top-3 有什么问题？

粗召回先取 20~50 条，精度低，直接取 top-3 可能漏掉相关但排序靠后的内容。重排模型对粗召回结果精排，再取 top-3~5 进 prompt，能明显提升答案和引用的准确率。

### 7. RAG 和模型微调怎么选？

RAG 解决"知识"问题：私有数据、最新信息、可溯源、可随时更新；微调解决"风格、格式、行为"问题。多数业务先用 RAG + 提示工程，效果不够再考虑微调。

### 8. 怎么证明你的 RAG 有效？

准备 30~50 道带答案来源的测试题，统计检索命中率、答案忠实度、引用准确率；再做对比实验：同一批问题直接问大模型 vs RAG 带引用，比较谁更准、幻觉更少。
